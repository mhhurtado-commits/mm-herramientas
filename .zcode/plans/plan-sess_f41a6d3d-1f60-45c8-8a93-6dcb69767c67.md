# Plan: Textbox de contexto + edición iterativa de imágenes

## Objetivo
Dos funcionalidades sobre la generación de imágenes:
1. **(A) Contexto previo**: un textbox donde el usuario aporta contexto o ajustes visuales ANTES de generar (se suma al prompt de Gemini). Regenera desde cero.
2. **(B) Edición iterativa**: sobre la imagen ya generada, un campo "Proponer cambios" que refina ESA imagen preservando la composición, vía **Pollinations Kontext** (FLUX Kontext, gratis). Permite ciclos editar→ver→editar.

## Desafío técnico resuelto
Kontext requiere la imagen previa por **URL pública** (no acepta base64). Solución: el worker guarda la imagen generada en KV bajo `imgtemp:{id}` (TTL 30 min) y la sirve en un nuevo endpoint público `GET /img-temp/{id}`. Kontext la toma de ahí. KV soporta hasta 25 MB por clave (suficiente para JPEG). Sigue el patrón existente de `handleSMNIcon`.

## Cambios

### Worker (`worker/worker.js`)

**1. Nuevo endpoint GET `/img-temp/{id}`** (en el bloque GET del router, ~línea 4384)
Sirve la imagen temporal como binario `image/jpeg`. Lee `imgtemp:{id}` de KV, hace `atob` y devuelve `new Response(bytes, {Content-Type:image/jpeg, Cache-Control:no-store})`. Público (sin auth). Si no existe → 404.

**2. `handleGenerarImagen` ampliado**:
- Recibe nuevo campo opcional `contexto_extra` → se concatena al `contexto` que se pasa a `construirPromptVisualGemini`. Esto implementa **(A)**.
- Tras generar, **guarda la imagen en KV** como `imgtemp:{id}` con `expirationTtl:1800` (30 min) y devuelve `imgTempId` en el JSON. El id = `imgtemp_<timestamp>_<random>`.

**3. Nuevo endpoint POST `/editar-imagen`** → nueva función `handleEditarImagen(body,env)`:
- Recibe `{imgTempId, instruccion}`.
- Construye la URL pública: `https://mm-herramientas-worker.mhhurtado.workers.dev/img-temp/{imgTempId}` (constante nueva `PUBLIC_WORKER_URL`).
- Llama a Pollinations: `https://image.pollinations.ai/prompt/{instruccion_en_inglés}?model=kontext&image={URL}&width=1200&height=630&nologo=true&seed={seed}`. Pre-procesa la instrucción con Gemini (la traduce a inglés y la enriquece levemente para mejor adherencia).
- **Fallback defensivo**: si Kontext falla/rate-limita (HTTP no ok), intenta `@cf/runwayml/stable-diffusion-v1-5-img2img` con `strength:0.45` (preserva composición) usando la imagen recuperada de KV. Así nunca se rompe, aunque el usuario eligió Kontext como primario.
- Al editar, **sobrescribe** el KV `imgtemp:{imgTempId}` con la nueva imagen → permite seguir refinando iterativamente sobre la última versión.
- Devuelve `{imagen, modelo, motor, imgTempId}`.
- Maneja rate-limit de Kontext (1 req/15s anónimo) con mensaje claro si ocurre.

**4. Router**: agregar `if(path==="/editar-imagen") return handleEditarImagen(body,env);` en el bloque POST, y `if(path.startsWith("/img-temp/")) return handleImgTemp(url,env);` en el bloque GET.

### Frontend (`redaccion/index.html`)

**5. Textbox de contexto previo (A)** — en `img-content-ia`, debajo del selector de estilo y el botón Generar:
```html
<div style="margin-bottom:8px">
  <div class="ref-section-label">Contexto visual (opcional)</div>
  <textarea id="img-contexto-extra" class="mm-textarea" rows="2"
    placeholder="Ej: mostrar de noche con luces de la ciudad, tonos cálidos de atardecer, ángulo cenital...">
  </textarea>
</div>
```
`generarImagenIA()` lee ese valor y lo envía como `contexto_extra`.

**6. UI de edición iterativa (B)** — debajo de `ref-img-preview`, aparece **solo después de generar/editar**:
```
┌─────────────────────────────────────────┐
│ ✏ Refinar imagen                        │
│ [textarea: Proponer cambios a esta imagen]│
│ [Refinar] [↺ Empezar de nuevo]           │
└─────────────────────────────────────────┘
```
- `refinarImagen()` llama a `/editar-imagen` con el `imgTempId` actual + la instrucción, reemplaza la preview, actualiza el canvas, y guarda el nuevo `imgTempId` para poder seguir refinando.
- "Empezar de nuevo" limpia la cadena de edición y vuelve a la generación original.
- Muestra el motor usado en el badge (`Kontext · Pollinations` o `img2img · Cloudflare AI`).
- El badge de la imagen ya generada ahora incluye `· ✏ editable`.

### No se toca
- La pestaña ⚙ Prompts, el canvas compositor, el logo, la descarga, y todo el flujo de reformular.
- No se agregan API keys nuevas: Kontext es gratis vía Pollinations, el fallback img2img usa `env.AI` ya configurado.

1. Generar una imagen → confirmar que el badge dice "· ✏ editable" y aparece la zona "Refinar imagen".
2. Probar (A): escribir contexto visual previo ("de noche, lluvia") → generar → la imagen refleja el contexto.
3. Probar (B): escribir "agregar montañas al fondo" → Refinar → la composición se preserva y aparecen montañas. Refinar de nuevo ("tonos de atardecer") → itera sobre la anterior.
4. Verificar que `/img-temp/{id}` responde 404 tras 30 min.
5. Probar el fallback: si Kontext rate-limita, debe caer a img2img de CF sin error visible.
