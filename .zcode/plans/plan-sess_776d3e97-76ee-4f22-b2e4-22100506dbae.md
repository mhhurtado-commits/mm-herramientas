# Plan: Editor de Mini-Web "Publicación" (publicación diseñable)

## Objetivo
Convertir la actual "Publicación Web / Rica" (que hoy solo *auto-genera* tarjetas de solo
lectura) en un **editor visual** donde la publicación completa — gráfico + mapa + cronología +
infografía — queda editable: una **base automática fuerte** + un **editor ligero** para
reorganizar, reestilizar y enriquecer con íconos, ilustraciones y texto. El resultado se exporta
como una **mini web HTML autónoma e interactiva** (y opcionalmente PNG).

## Restricciones (vigentes)
- **NO** tocar el modelo de Gemini que usa toda la suite en `worker/worker.js`.
- Las ilustraciones por IA usan un **modelo DIFERENTE** vía una **NUEVA ruta** del worker
  (`/visual/ilustrar`), sin alterar el modelo ni las rutas existentes.
- Mantener `--v:#a6ce39` en la UI de la app; solo pueden variar los colores de la mini web/placas.
- Reusar código existente: `recogerDatos()` (publicacion.js), `construirHTMLWeb()`,
  `recursos.js` (íconos SVG + ilustraciones PNG), y los patrones de drag/resize de `logoState`.

## Interpretación de "editable" (para fijar expectativas)
- **Infografía (tarjetas/listado/comparativa/destacado):** editable libremente — mover,
  redimensionar, agregar/quitar tarjetas, íconos y texto.
- **Gráfico / Mapa / Cronología:** se pueden reordenar como bloques, mostrar/ocultar,
  recolorear y recibir overlays de íconos/ilustraciones/texto encima; NO se redibuja el interior
  del chart/mapa (mantiene el scope razonable). Esto cumple "Ambos": base automática + editor
  ligero sobre esa base.

## Arquitectura
1. **Modelo `window.pubState`** (documento editable de la publicación):
   ```
   pubState = {
     titulo,
     secciones: [ { id, tipo:'chart'|'map'|'timeline'|'infografia',
                    visible, datos, estilo:{color1,color2,plantilla}, orden } ],
     bloques: [ { tipo:'icono'|'ilustracion'|'texto'|'forma',
                  x,y,w,h, z, contenido, ... } ],   // elementos añadidos a mano
     logo, generado
   }
   ```
2. **UI del editor** (nueva pestaña/sección "Editor de Publicación" en `index.html`, con modal
   o vista propia):
   - **Izquierda (paleta/inspector):** agregar ícono, ilustración (librería / IA), texto, forma;
     toggles de visibilidad por sección; selector de plantilla y colores; capa/z-order.
   - **Centro (Stage):** la mini web editable renderizada en vivo (bloques posicionados).
   - **Arriba:** "Auto-generar base", reordenar (drag), "Exportar mini web", "Exportar PNG".
3. **Render del Stage:** cada sección se dibuja con los renderers que ya existen
   (chart→Chart.js, mapa→Leaflet, timeline→`buildTimeline` DOM, infografia→`buildInfografia` DOM),
   reusados dentro de bloques `position:absolute` sobre un contenedor Stage.
4. **Interacciones (reusar patrón de `logoState`):** drag para mover, handles de esquina para
   redimensionar, edición de texto inline (`contentEditable`), reordenar bloques, z-order.
   Cada cambio actualiza `pubState` y re-renderiza.
5. **Librería gráfica:**
   - Reusar `recursos.js`: `generarIconosSVG` (set de íconos SVG emoji-en-círculo) y
     `generarIlustracionesPNG` (ilustraciones canvas desde datos) → paleta para soltar.
   - **NUEVO:** ilustraciones por IA vía `/visual/ilustrar` en el worker con un modelo de imagen
     distinto (p. ej. un modelo image-capable de Gemini). Devuelve PNG dataURL para soltar en el
     Stage. Input de prompt (reusar concepto de `#ricaPrompt`) + categoría.
6. **Export:**
   - Extender `construirHTMLWeb(pubState)` para emitir bloques posicionados + `bloques` extra →
     HTML autónomo interactivo (Chart.js + Leaflet por CDN, logo como dataURI, igual que hoy).
   - PNG opcional del Stage vía `html2canvas` a **scale 2–3** (evita el bloat de 1.9–5.7 MB
     visto antes con scale:4).
   - Mantener "Publicación Rica" (galería descargable) como una opción de export adicional.

## Pasos de implementación (orden sugerido)
1. Ampliar `recogerDatos()` → sembrar `pubState` con base automática desde chart/map/timeline/infografia.
2. Crear shell del editor en `index.html` + estilos + wiring en `app.js` (pestaña/modal, paleta, Stage).
3. Renderizar las secciones-base como bloques en el Stage (reusar renderers existentes).
4. Drag / resize / reorder + edición inline de bloques de sección.
5. Paleta gráfica: soltar íconos (SVG), ilustraciones (PNG), texto y formas; control de z-order.
6. **Worker:** agregar ruta `/visual/ilustrar` con modelo de imagen DIFERENTE (sin tocar el modelo
   ni rutas actuales de la suite). Cliente: llamada + inserción en Stage.
7. Extender `construirHTMLWeb` para emitir posiciones + `bloques` → export mini web.
8. Export PNG del Stage (html2canvas scale 2–3).
9. Pruebas end-to-end (Playwright): generar base desde datos, agregar ícono/ilustración, reordenar,
   exportar HTML y verificar que abre y renderiza; verificar que la nueva ruta NO rompe el modelo
   existente de la suite.

## Riesgos / notas
- **Worker:** solo AGREGAR una ruta; no cambiar `callGemini` ni las rutas existentes.
- El PNG de placas anteriores estaba sobredimensionado (mapa 1.9 MB, destacado 5.7 MB): el export
  HTML no tiene ese problema (es texto); el PNG del Stage usa scale 2–3.
- No puedo verificar visualmente el render (el modelo no acepta imágenes): me apoyaré en medición
  de DOM/canvas y chequeos estructurales durante las pruebas.
- (Opcional, fuera de alcance inicial) inline de Chart.js/Leaflet para mini web 100% offline.
